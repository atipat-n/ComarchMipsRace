> [!IMPORTANT]
> - **เวลานำเสนอ:** 10–15 นาที + ช่วงถาม-ตอบ 5–10 นาที (ตามเกณฑ์รายวิชาใน [`spec.md`](spec.md) หัวข้อ 17)

> - **รูปแบบตัวเลขบนจอ:** จอ VGA แสดงเวลา `TIME` เป็น **เลขฐานสิบหก (Hexadecimal)** ตารางด้านล่างจึงมีให้ครบทั้งเลขฐานสิบและเลขฐานสิบหก

## ✅ 0. เช็กลิสต์เตรียมความพร้อมก่อนขึ้นเวที

- [ ] โหลด Bitstream ลงบอร์ดแล้ว (`fpga\run.bat top program`) และต่อสาย VGA เข้ากับจอภาพหรือโปรเจกเตอร์เรียบร้อย
- [ ] ตั้งสวิตช์เริ่มต้น:
  - **`SW15 = 0`** (ลง — Step Mode)
  - **`SW14–12 = 011`** (ความเร็วระดับ 3)
  - **`SW4 = 0`** (ลง — โปรแกรม A)
  - **`SW3–0 = 0000`** (ลงหมด — `ov = 0`)
- [ ] กดปุ่มแดง **`CPU_RESETN`** 1 ครั้ง → แถวบนสุดของจอต้องขึ้น `PROG A  OV 0  TIME 00000000`
- [ ] เปิดไฟล์เว็บ [`web/index.html`](../web/index.html) และคลิปวิดีโอสำรองเตรียมไว้ในโน้ตบุ๊กเผื่อกรณีฉุกเฉิน
- [ ] พกหัวแปลง VGA → HDMI สำรองติดตัวไว้เสมอ

### 🎛️ ตารางปุ่มกดและสวิตช์ที่ใช้ระหว่างสาธิต

| ปุ่ม / สวิตช์ | ตำแหน่ง | หน้าที่การทำงาน |
|---|:---:|---|
| **`BTNC`** | ปุ่มกลาง | **Step:** ก้าวเวลาไปยังเหตุการณ์ถัดไป 1 จังหวะ (ใช้เมื่อ `SW15 = 0`) |
| **`BTNR`** | ปุ่มขวา | **Run / Pause:** เริ่มวิ่งแข่งขันหรือหยุดชั่วคราว (ใช้เมื่อ `SW15 = 1`) |
| **`BTNL`** | ปุ่มซ้าย | **Reload / Reset:** โหลดโปรแกรมใหม่และรีเซ็ตเวลาเป็น `0` *(ต้องกดทุกครั้งหลังเปลี่ยน `SW4` หรือ `ov`)* |
| **`BTNU`** | ปุ่มบน | **7-Seg Toggle:** สลับตัวเลขบน 7-Segment ระหว่าง *"จำนวนคำสั่งที่ทำเสร็จ"* กับ *"เวลา"* |
| **`SW3–0`** | ขวาล่างสุด 4 ตัว | ตั้งค่า **`ov` (Register Overhead `0–15`)** เช่น `0000` = 0, `0100` = 4, `0110` = 6 |
| **`SW4`** | ถัดจาก `SW3` | เลือกโปรแกรม: **ลง (`0`) = โปรแกรม A (ALU heavy)**, **ขึ้น (`1`) = โปรแกรม B (Memory heavy)** |
| **`SW15`** | ซ้ายสุด | เลือกโหมด: **ลง (`0`) = Step Mode**, **ขึ้น (`1`) = Run Mode** |

## 2. แนะนำระบบของเรา (นาทีที่ `1:30 – 4:00`)

- **ชี้ที่จอ VGA:**
  - **ฝั่งซ้าย (สีส้ม):** Single-cycle MIPS (วาดตามรูป Datapath ในสไลด์ `w04a`)
  - **ฝั่งขวา (สีฟ้า):** Multicycle MIPS (วาดตามรูป Datapath ในสไลด์ `w04c` หน้า 3)
- **อธิบายการแสดงผล:** เส้นที่ **ติดสีสว่าง** คือเส้นทางที่ข้อมูลกำลังวิ่งผ่านจริงในวงจรขณะนั้น
- **อธิบายฮาร์ดแวร์:** ทั้งสอง CPU เขียนขึ้นเองด้วย Verilog อยู่ในชิป FPGA ตัวเดียวกัน รันโปรแกรมเดียวกันไปพร้อมๆ กัน
- **อธิบายโมเดลเวลา:**
  - 🟠 **Single-cycle:** ใช้เวลา **`50 + ov`** ต่อคำสั่ง
  - 🔵 **Multicycle:** ใช้เวลา **`10 + ov`** ต่อ Step (โดย `ov` คือเวลาที่สูญเสียทุกครั้งที่ข้อมูลวิ่งผ่าน Register)

## 3. Demo 1: กดทีละ Step ดูการทำงานข้างใน (นาทีที่ `4:00 – 6:00`)

> **การตั้งค่าสวิตช์:** `SW15 = 0` (Step Mode), `SW4 = 0` (โปรแกรม A), `SW3–0 = 0000` (`ov = 0`)

> [!TIP]
> จอ VGA จะแสดงสิ่งที่ CPU **"กำลังจะทำในจังหวะถัดไป"** เสมอ (เส้นที่ติดสีคือเส้นที่กำลังจะถูกใช้งานเมื่อกดปุ่มครั้งต่อไป)

| กด `BTNC` ครั้งที่ | `TIME` บนจอ (Hex / Dec) | เหตุการณ์ที่เกิดขึ้น | สิ่งที่แสดงบนจอ (ฝั่ง Multicycle) |
|:---:|:---:|---|---|
| ยังไม่กด | `00` (`0`) | สถานะเริ่มต้นหลังรีเซ็ต | **`FETCH`**: `PC → MEM → IR`, `ALU` บวก `PC+4` *(ฝั่ง Single โชว์ทางเดินของ `addi` คำสั่งแรก)* |
| **ครั้งที่ 1** | `0A` (`10`) | Multicycle ทำ `FETCH` เสร็จ | **`DECODE`**: `IR → REG → A, B` |
| **ครั้งที่ 2** | `14` (`20`) | Multicycle ทำ `DECODE` เสร็จ | **`ADDI_EXEC`**: `A + EXT → ALU` |
| **ครั้งที่ 3** | `1E` (`30`) | Multicycle ทำ `ADDI_EXEC` เสร็จ | **`ADDI_WB`**: `ALUOut → REG` |
| **ครั้งที่ 4** | `28` (`40`) | 🏆 **Multicycle ทำคำสั่ง `addi` แรกเสร็จ!** (`RETIRED M = 1`) | วนกลับไป **`FETCH`** คำสั่งที่ 2 |
| **ครั้งที่ 5** | `32` (`50`) | 🟠 **Single-cycle เพิ่งทำ `addi` แรกเสร็จ** (`RETIRED S = 1`) พร้อมกับที่ Multi ทำ `FETCH` เสร็จ | **`DECODE`** คำสั่งที่ 2 |

> 🗣️ **บทสรุปช่วงที่ 1:** *"สังเกตว่า Multicycle ทำคำสั่งแรกเสร็จตั้งแต่วินาทีที่ 40 แต่ Single-cycle ต้องรอถึง 50 เพราะ Clock ของ Single-cycle ถูกบังคับให้ยาวเท่ากับคำสั่งที่ช้าที่สุดคือ `lw`"*

## 4. Demo 2: วิ่งแข่งจริงบนโปรแกรม A (นาทีที่ `6:00 – 9:00`)

1. โยก **`SW15 = 1`** (ขึ้น — Run Mode) → กด **`BTNL`** (เริ่มใหม่) → กด **`BTNR`** (เริ่มวิ่ง) รอประมาณ 15 วินาที
2. **ผลลัพธ์ที่ `ov = 0`:** 🔵 **Multicycle ชนะขาดลอย!** (ขึ้นคำว่า `WINNER` ที่แถว `M`)
3. **ถามผู้ฟังในห้อง:** *"ถ้าทุกครั้งที่ข้อมูลผ่าน Register ต้องเสียเวลาค่าผ่านทาง (`ov`) เพิ่มขึ้นอีก 4 หน่วย คิดว่าใครจะชนะ? แล้วถ้าเพิ่มเป็น 6 ล่ะ?"*
4. โยก **`SW2` ขึ้น** (`SW3–0 = 0100`, `ov = 4`) → กด **`BTNL`** → กด **`BTNR`** → 🔵 **Multicycle ยังชนะอยู่** แต่ระยะห่างแคบลงมาก
5. โยก **`SW1` ขึ้นเพิ่ม** (`SW3–0 = 0110`, `ov = 6`) → กด **`BTNL`** → กด **`BTNR`** → 🟠 **Single-cycle แซงกลับมาชนะ! ผลการแข่งพลิกกลับทันที**

| โปรแกรม | ค่า `ov` | ตำแหน่งสวิตช์ `SW3–0` | เวลาจบ 🟠 Single (ฐานสิบ / Hex บนจอ) | เวลาจบ 🔵 Multi (ฐานสิบ / Hex บนจอ) | ผู้ชนะบนจอ |
|:---:|:---:|:---:|:---:|:---:|:---:|
| **A** | `0` | `0000` | `2800` / **`AF0`** | **`2030` / `7EE`** | 🔵 **Multi (`WINNER`)** |
| **A** | `4` | `0100` (`SW2` ขึ้น) | `3024` / **`BD0`** | **`2842` / `B1A`** | 🔵 **Multi (`WINNER`)** |
| **A** | `5` | `0101` (`SW2, SW0` ขึ้น) | `3080` / **`C08`** | **`3045` / `BE5`** | 🔵 **Multi** *(เฉือนชนะ 35 หน่วย)* |
| **A** | `6` | `0110` (`SW2, SW1` ขึ้น) | **`3136` / `C40`** | `3248` / **`CB0`** | 🟠 **Single (`WINNER`)** |

## 5. Demo 3: เปลี่ยนเป็นโปรแกรม B — ค่า `ov` เท่าเดิมแต่ผลกลับด้าน! (นาทีที่ `9:00 – 10:30`)

1. ตั้งค่า `ov = 4` (`SW3–0 = 0100`, โยกเฉพาะ `SW2` ขึ้น)
2. โยก **`SW4` ขึ้น (`1` = โปรแกรม B)** → กด **`BTNL`** → กด **`BTNR`**
3. **ผลลัพธ์:** 🟠 **Single-cycle เป็นฝ่ายชนะ!** ทั้งที่ใช้ค่า `ov = 4` เท่ากับตอนที่โปรแกรม A ให้ Multicycle ชนะ

| โปรแกรม | ค่า `ov` | เวลาจบ 🟠 Single (ฐานสิบ / Hex) | เวลาจบ 🔵 Multi (ฐานสิบ / Hex) | ผู้ชนะบนจอ |
|:---:|:---:|:---:|:---:|:---:|
| **B** | `0` | `1850` / **`73A`** | **`1470` / `5BE`** | 🔵 **Multi (`WINNER`)** |
| **B** | `3` | `1961` / **`7A9`** | **`1911` / `777`** | 🔵 **Multi (`WINNER`)** |
| **B** | `4` | **`1998` / `7CE`** | `2058` / **`80A`** | 🟠 **Single (`WINNER`)** |

### 📐 อธิบายด้วยสมการประสิทธิภาพ (สไลด์ `w01b` หน้า 12)

$$\text{Time} = \text{IC} \times \text{CPI} \times T$$

| ตัวแปร | โปรแกรม A (ALU heavy) | โปรแกรม B (Memory heavy) |
|---|---|---|
| **จำนวนคำสั่ง (`IC`)** | 56 คำสั่ง | 37 คำสั่ง |
| **`CPI` เฉลี่ยของ Multicycle** | **`3.63`** (มีคำสั่ง `beq`/`j` ที่ใช้ 3 step เยอะ) | **`3.97`** (มีคำสั่ง `lw` ที่ใช้ 5 step เยอะ) |
| **เงื่อนไขที่ Multicycle ชนะ** | $3.63 \times (10 + \text{ov}) < 50 + \text{ov} \implies \mathbf{\text{ov} \le 5}$ | $3.97 \times (10 + \text{ov}) < 50 + \text{ov} \implies \mathbf{\text{ov} \le 3}$ |

> 🗣️ **ประโยคสรุปไฮไลต์:** *"ใครเร็วกว่าไม่ได้ขึ้นอยู่กับจำนวน Clock เพียงอย่างเดียว แต่ต้องดูด้วยว่าแต่ละ Clock ยาวเท่าไร ($T$) และโปรแกรมใช้งานคำสั่งประเภทไหนเป็นหลัก ($\text{CPI}$)"*

## 6. เบื้องหลังการออกแบบและตรวจสอบ (นาทีที่ `10:30 – 13:00`)

- **FSM 12 States ของ Multicycle:** ขยายจากตาราง 5 Steps ในสไลด์ `w04c` โดยเพิ่มสถานะสำหรับคำสั่ง `addi` อีก 2 States (`S10 ADDI_EXEC`, `S11 ADDI_WB`)
- **เทคนิคการวาดจอแบบ Wire-ID:** ภาพพื้นหลังใน BRAM เก็บ *"รหัสประจำเส้น"* แทนค่าสี แล้วให้วงจรเลือกสีส้ม/ฟ้า/เทาตามบิตสัญญาณ `active` จาก CPU แบบสดๆ จึงไม่ต้องใช้วงจรคำนวณพิกัดเส้นที่ซับซ้อน
- **การตรวจความถูกต้อง 4 ทาง (`run_all.py`):** ทุกโปรแกรมรันเทียบผลพร้อมกันบน (1) `ref_model.py` (2) **`cpuSim V7` ของอาจารย์** (3) `single_cycle_cpu.v` และ (4) `multi_cycle_cpu.v` โดยค่า Register ทั้ง 32 ตัวและข้อมูลใน Memory ต้องตรงกันทั้งหมด
- **การแก้ปัญหาทางเทคนิค:**
  1. พบว่าสไลด์ `w04c` พิมพ์รหัส `funct` ของคำสั่ง `slt` เป็น `0xA` ซึ่งค่าจริงตามมาตรฐานและใน `cpuSim` คือ **`0x2A`**
  2. เขียน Adapter เติมคำสั่ง `SUB`, `AND`, `OR`, `SLT` ให้ `cpuSim V7` โดยไม่แก้ไขไฟล์ต้นฉบับของอาจารย์
  3. เปลี่ยนหน่วยความจำของ CPU จาก BRAM เป็น **LUTRAM** เพื่อให้ Single-cycle อ่านคำสั่งและข้อมูลได้ทันทีภายใน 1 Clock

## 7. สรุปปิดท้าย (นาทีที่ `13:00 – 15:00`)

- **Multicycle CPU** ช่วยลดความยาว Clock และประหยัดฮาร์ดแวร์ด้วยการใช้วงจรซ้ำ (`ALU` ตัวเดียว, `Memory` ก้อนเดียว)
- แต่หาก **Register Overhead (`ov`) สูงเกินไป** การซอยจังหวะย่อยมากเกินไปจะทำให้เสียเวลาสะสมจนช้ากว่าเดิม (เหมือนกรณี *Megahertz Myth* ในยุค Pentium 4)
- **แนวทางต่อยอด:** สถาปัตยกรรม **Pipelining** (สไลด์ `w04c_pipeline`) ซึ่งแบ่งจังหวะย่อยเหมือน Multicycle แต่ให้หลายคำสั่งเหลื่อมซ้อนทำงานไปพร้อมกันเพื่อให้ได้ทั้ง Clock ที่สั้นและ $\text{CPI} \approx 1$

| คำถามที่อาจถูกถาม | แนวทางคำตอบที่ชัดเจน |
|---|---|
| **ทำไมไม่ปล่อยให้แต่ละ CPU วิ่งด้วยความถี่ Clock จริงที่ต่างกันบนบอร์ด?** | บนบอร์ดทั้งสองตัวอยู่ในชิปเดียวกันและใช้ Clock 25 MHz ร่วมกันเพื่อให้วาดออกจอ VGA พร้อมกันได้โดยไม่มีปัญหาข้าม Clock Domain (CDC) และเพื่อให้คนดูมองเห็นทัน จึงใช้วงจร `race_ctrl` จำลองหน่วยเวลาแยกออกมา (`50 + ov` เทียบกับ `10 + ov`) |
| **ค่า `ov` ในโลกของฮาร์ดแวร์จริงคืออะไร?** | คือเวลาที่สูญเสียทุกครั้งที่ข้อมูลต้องล็อกผ่าน Flip-Flop หรือ Register ได้แก่ *Setup time* ($t_{su}$), *Clock-to-Q delay* ($t_{cq}$) และความคลาดเคลื่อนของสัญญาณนาฬิกา (*Clock skew*) |
| **ทำไมคำสั่ง `lw` ใน Single-cycle ถึงกำหนดให้ใช้ 50 หน่วยเวลา?** | เพราะ `lw` เป็นเส้นทางวิกฤต (Critical Path ตามสไลด์ `w04a` หน้า 36) ที่ต้องผ่านครบทั้ง 5 ส่วน (`IMEM → REG → ALU → DMEM → REG`) เมื่อสมมติให้แต่ละส่วนใช้เวลา 10 หน่วย จึงรวมเป็น 50 หน่วยเวลา |
| **คำสั่ง `beq` ใน Multicycle ใช้ 3 Steps เสมอไม่ว่าจะกระโดดหรือไม่กระโดดใช่ไหม?** | ใช่ครับ เพราะใน `S1 DECODE` วงจร `ALU` คำนวณตำแหน่งเป้าหมาย Branch เก็บไว้ใน `ALUOut` ล่วงหน้าแล้ว พอถึง `S8 BRANCH` (Step ที่ 3) จึงแค่เอาค่า `A` กับ `B` มาลบเทียบกัน ถ้าเท่ากันก็เขียนค่า `ALUOut` ลง `PC` แล้วจบใน Step ที่ 3 ทันทีทั้งสองกรณี |
| **มั่นใจได้อย่างไรว่าวงจร CPU ที่เขียนเองทำงานถูกต้อง 100%?** | เราตรวจสอบเทียบ 4 ทาง (`ref_model`, `cpuSim` ของอาจารย์, `Single-cycle RTL`, `Multicycle RTL`) ด้วยโปรแกรมทดสอบ 13 โปรแกรม และยังทดลองแกล้งใส่วงจรที่ผิด (Fault Injection ในคำสั่ง `slt`) เพื่อพิสูจน์ว่าชุดทดสอบสามารถตรวจจับบั๊กได้จริง |
| **ใช้ IP สำเร็จรูปของ Vivado ช่วยสร้าง CPU หรือไม่?** | ไม่ได้ใช้เลยครับ โค้ด CPU, FSM, Memory, UART และตัววาดจอ VGA ทั้งหมดเขียนเองด้วย Verilog-2001 ล้วน มีเพียงการใช้ Primitive `MMCME2_BASE` เพื่อแปลงความถี่ Clock จาก 100 MHz เป็น 25 MHz สำหรับจอ VGA เท่านั้น |
| **ทำไมตัวเลขเวลา `TIME` บนจอ VGA จึงแสดงเป็นเลขฐานสิบหก (Hex)?** | เพราะการแปลงเลข 32-bit เป็นเลขฐานสิบในฮาร์ดแวร์ต้องใช้วงจรแปลง BCD (Double-dabble) ขนาดใหญ่ เราจึงแสดงค่าจาก Register เป็น Hex โดยตรง (1 หลัก Hex = 4 บิต) และเตรียมตารางเทียบเลขฐานสิบควบคู่กับฐานสิบหกไว้บนสไลด์ครับ |
