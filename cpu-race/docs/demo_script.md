# สคริปต์นำเสนอ + วิธีเล่น demo บนบอร์ด

> เวลา 10–15 นาที + ถาม-ตอบ 5–10 นาที (สเปคหัวข้อ 17)
> ตัวเลขทุกตัวในไฟล์นี้มาจาก `python tools/race_calc.py` และยืนยันด้วยการจำลองทั้งบอร์ดใน `python sim/run_all.py`
> **จอแสดงเวลาเป็นเลขฐานสิบหก** ตารางด้านล่างมีให้ทั้งสองแบบ

---

## 0. เตรียมก่อนขึ้นเวที

- [ ] โหลด bitstream ลงบอร์ดแล้ว (`fpga\run.bat top program` ที่เครื่องเพื่อน) ต่อสาย VGA เข้าจอ
- [ ] สวิตช์ตั้งต้น: **SW15 = 0** (step mode), **SW14–12 = 011** (ความเร็ว 3), **SW4 = 0** (โปรแกรม A), **SW3–0 = 0000** (ov = 0)
- [ ] กดปุ่มแดง **CPU_RESETN** หนึ่งครั้ง → จอขึ้น `PROG A  OV 0  TIME 00000000`
- [ ] เปิดคลิปสำรองไว้ในเครื่อง เผื่อบอร์ด/จอมีปัญหา
- [ ] พกตัวแปลง VGA ไปด้วย

**ปุ่มที่ใช้:**

| ปุ่ม / สวิตช์ | ทำอะไร |
|---|---|
| BTNC (กลาง) | step: กระโดดไปเหตุการณ์ถัดไป (ใช้ตอน SW15 = 0) |
| BTNR (ขวา) | เริ่ม / หยุด การวิ่ง (ใช้ตอน SW15 = 1) |
| BTNL (ซ้าย) | โหลดโปรแกรมใหม่ + เวลากลับเป็น 0 (**กดทุกครั้งหลังเปลี่ยน SW4 หรืออยากเริ่มใหม่**) |
| BTNU (บน) | สลับ 7-seg ระหว่าง "จำนวนคำสั่ง" กับ "เวลา" |
| SW3–0 | ค่า ov (0–15) |
| SW4 | โปรแกรม A (ลง) / B (ขึ้น) |

## 1. คำถามเปิด (0:00–1:30)

> "CPU สองตัว ตัวหนึ่งใช้ **1 clock ต่อคำสั่ง** อีกตัวใช้ **3–5 clock ต่อคำสั่ง** ตัวไหนเร็วกว่า?"

ให้ห้องยกมือโหวต (ส่วนใหญ่จะตอบตัวแรก) แล้วบอกว่า "เดี๋ยวให้บอร์ดตอบ"

## 2. ระบบของเรา (1:30–4:00)

- ชี้จอ: ซ้าย = single-cycle (รูปเดียวกับสไลด์ w04a), ขวา = multicycle (สไลด์ w04c หน้า 3)
- เส้นที่ **ติดสี** คือเส้นที่ข้อมูลกำลังวิ่งผ่านจริงในวงจร (ส้ม = single, ฟ้า = multi)
- ทั้งสอง CPU เป็นวงจรที่เราเขียนเอง (Verilog) อยู่ในชิปตัวเดียวกัน รันโปรแกรมเดียวกัน
- โมเดลเวลา: single ใช้ **50 + ov** ต่อคำสั่ง, multi ใช้ **10 + ov** ต่อ step (ov = เวลาที่เสียทุกครั้งที่ข้อมูลผ่าน register)

## 3. Demo 1: กดทีละ step (4:00–6:00)

สวิตช์: SW15 = 0, โปรแกรม A, ov = 0 (ตั้งไว้แล้ว)

จอแสดงสิ่งที่ CPU **กำลังจะทำ** ในจังหวะถัดไปเสมอ (เส้นที่ติดคือเส้นที่จะใช้)

| กด BTNC ครั้งที่ | TIME | เกิดอะไร | จอโชว์ (ฝั่ง multi) |
|---|---|---|---|
| ยังไม่กด | 00 (0) | – | FETCH: PC → MEM → IR, ALU บวก PC+4 (ฝั่ง single โชว์ `addi` คำสั่งแรก) |
| 1 | 0A (10) | multi ทำ FETCH เสร็จ | DECODE: IR → REG → A, B |
| 2 | 14 (20) | multi ทำ DECODE เสร็จ | ADDI_EXEC: A + EXT → ALU |
| 3 | 1E (30) | multi ทำ ADDI_EXEC เสร็จ | ADDI_WB: ALUOut → REG |
| 4 | 28 (40) | **multi ทำ addi แรกเสร็จ** (RETIRED ของ M = 1) | FETCH คำสั่งที่ 2 |
| 5 | 32 (50) | **single ทำ addi แรกเสร็จ** (RETIRED ของ S = 1) และ multi ทำ FETCH พร้อมกัน | DECODE |

พูด: "multi ทำคำสั่งแรกเสร็จที่เวลา 40 แต่ single เสร็จที่ 50 เพราะ clock ของ single ต้องยาวพอสำหรับคำสั่งที่ช้าที่สุด (lw)"

## 4. Demo 2: แข่งจริง (6:00–9:00)

1. **SW15 = 1** (run mode) → กด **BTNL** (เริ่มใหม่) → กด **BTNR** (วิ่ง) รอประมาณ 15 วินาที
2. ผล **โปรแกรม A, ov = 0:** multi ชนะ (ขึ้น WINNER ที่แถว M)
3. ถามห้อง: "ถ้าทุกครั้งที่ข้อมูลผ่าน register ต้องเสียเวลาเพิ่มอีก 4 หน่วยล่ะ?" → ให้ทาย
4. โยก **SW2 ขึ้น** (ov = 4) → BTNL → BTNR → **multi ยังชนะ** แต่ห่างกันน้อยลงมาก
5. โยก **SW1 ขึ้นเพิ่ม** (ov = 6) → BTNL → BTNR → **single ชนะ!** ผลพลิก

| โปรแกรม | ov | Single (ฐานสิบ / hex บนจอ) | Multi (ฐานสิบ / hex บนจอ) | ผู้ชนะ |
|---|---|---|---|---|
| A | 0 | 2800 / `AF0` | **2030 / `7EE`** | multi |
| A | 4 | 3024 / `BD0` | **2842 / `B1A`** | multi |
| A | 5 | 3080 / `C08` | **3045 / `BE5`** | multi (เฉือน 35) |
| A | 6 | **3136 / `C40`** | 3248 / `CB0` | **single** |

## 5. Demo 3: โปรแกรมต่าง ผลต่าง (9:00–10:30)

1. ตั้ง ov = 4 (SW3–0 = 0100) → **SW4 ขึ้น** (โปรแกรม B) → BTNL → BTNR
2. ผล: **single ชนะ** ทั้งที่ ov เท่ากับตอนที่ A ให้ multi ชนะ

| โปรแกรม | ov | Single | Multi | ผู้ชนะ |
|---|---|---|---|---|
| B | 0 | 1850 / `73A` | **1470 / `5BE`** | multi |
| B | 3 | 1961 / `7A9` | **1911 / `777`** | multi |
| B | 4 | **1998 / `7CE`** | 2058 / `80A` | **single** |

อธิบายด้วยสมการบนสไลด์ (w01b หน้า 12): **เวลา = IC × CPI × T**

| | A | B |
|---|---|---|
| จำนวนคำสั่ง (IC) | 56 | 37 |
| CPI ของ multi | 3.63 (มี beq/j 3 step เยอะ) | 3.97 (มี lw 5 step เยอะ) |
| multi ชนะเมื่อ | 3.63 × (10+ov) < 50+ov → ov ≤ 5 | 3.97 × (10+ov) < 50+ov → ov ≤ 3 |

> **ประโยคสรุป:** "ใครเร็วกว่าไม่ได้ขึ้นกับจำนวน clock อย่างเดียว ต้องดู clock ยาวเท่าไร (T) และโปรแกรมใช้คำสั่งแบบไหน (CPI)"

## 6. เบื้องหลัง (10:30–13:00)

- **FSM 12 state** ของ multicycle (สไลด์ 5 step + addi 2 state)
- **เทคนิค wire-ID:** ภาพพื้นหลังเก็บ "เลขประจำเส้น" แทนสี วงจรเลือกสีตามว่าเส้นนั้นทำงานไหม → ไม่ต้องวาดเส้นด้วยวงจร
- **ตรวจความถูกต้อง 4 ทาง:** ทุกโปรแกรมรันบน (1) reference model ที่เราเขียน (2) **cpuSim ของอาจารย์** (3) single-cycle (4) multicycle แล้วเทียบ register ทั้ง 32 ตัว + memory ต้องตรงกันหมด + เทียบกับค่าที่คิดด้วยมือ
- **ปัญหาที่เจอ:** สไลด์ w04c พิมพ์ funct ของ slt เป็น 0xA (จริงคือ 0x2A), cpuSim ยังไม่มี SUB/AND/OR/SLT เลยต้องเขียนส่วนเสริมครอบ, single-cycle ต้องใช้ memory ที่อ่านได้ทันที (LUTRAM) เพราะ BRAM อ่านช้าไป 1 clock

## 7. สรุป (13:00–15:00)

- multicycle: clock สั้น ใช้หลาย clock ต่อคำสั่ง ใช้ฮาร์ดแวร์ซ้ำได้ (ALU ตัวเดียว memory ก้อนเดียว)
- ถ้า overhead ของ register สูง การแบ่ง step เยอะๆ ไม่คุ้ม (เหมือน Pentium 4 ที่ GHz สูงแต่บางงานแพ้)
- ต่อยอด: **pipelining** (สไลด์ w04c_pipeline) = แบ่ง step แบบ multicycle แต่ให้หลายคำสั่งทำงานซ้อนกัน

## คำถามที่น่าจะโดนถาม

| คำถาม | คำตอบ |
|---|---|
| ทำไมไม่ใช้ clock จริงของแต่ละ CPU? | บนบอร์ดทั้งสองตัวใช้ clock เดียวกัน (25 MHz) ถ้าปล่อยเดินทุก clock จะไม่เห็นว่า single มี clock ยาวกว่า เลยจำลอง "เวลา" แยก: ตัวคุมการแข่งปล่อยให้ single เดินทุก 50+ov หน่วย multi ทุก 10+ov หน่วย |
| ov คืออะไรในโลกจริง? | เวลาที่เสียทุกครั้งที่ข้อมูลผ่าน flip-flop: setup time, clock-to-Q delay, clock skew |
| ทำไม lw ถึงใช้ 50 หน่วยใน single? | lw ผ่านครบ 5 ส่วน: IMEM → REG → ALU → DMEM → REG (critical path สไลด์ w04a หน้า 36) แต่ละส่วนสมมติ 10 หน่วย |
| beq ใน multi ใช้ 3 step ทั้งที่กระโดดหรือไม่กระโดด? | ใช่ step 3 (BRANCH) เทียบ A กับ B แล้วเขียน PC เฉพาะเมื่อเท่ากัน เป้าหมายคำนวณไว้ล่วงหน้าตั้งแต่ DECODE |
| รู้ได้ไงว่า CPU ถูก? | เทียบ 4 ทางรวม cpuSim ของอาจารย์ (`python sim/run_all.py`) และลองทำวงจรพังโดยตั้งใจแล้วเทสต์จับได้ |
| ใช้ CPU สำเร็จรูปไหม? | ไม่ ทุกอย่างเขียนเอง ใช้แค่ตัวคูณ clock (MMCM) ที่อยู่ในชิป |
| ภาพบนจอวาดยังไง? | สคริปต์ Python วาดเส้นและกล่อง ให้ทุกเส้นมีเลขประจำตัว (wire-ID) เก็บลง BRAM วงจรอ่านเลขนี้ทีละ pixel แล้วเลือกสีตามสัญญาณ active จาก CPU |
| ทำไมเวลาเป็นเลขฐานสิบหก? | แปลงเป็นฐานสิบต้องใช้วงจรเพิ่ม (double-dabble) เลยแสดง hex ตรงๆ ตารางในสไลด์มีทั้งสองแบบ |
